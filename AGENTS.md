# Project rules
- Restrição de áreas de usuários de leitura fica em `user_secretarias` vinculada por e-mail em minúsculas (o usuário pode ainda não estar registrado); a política de leitura de protocolos trata ausência de vínculos como acesso a todas as áreas e exclui ouvidorias sem secretaria de usuários restritos.
- O mapa filtra os botões Saúde/Obras pelas áreas do usuário via `escoposMapaPermitidos` em src/lib/map-departments.ts, consultando `user_secretarias` sempre com filtro do próprio e-mail (admin enxerga vínculos de todos pela RLS, então sem o filtro ele herdaria escopo alheio).
- `secretarias` e `locais` têm policy de SELECT para `authenticated` (além da de `anon`): sem ela, usuários não-admin veem as telas Saúde e Mapa vazias, pois essas telas leem as duas tabelas diretamente.
- Full e-SIC mailbox backfills use resumable bounded requests across all provider pages/folders, separate from incremental sync cursors; reuse ingestion with original received dates and never reprocess linked logs.
- Enforce e-SIC identifier equality in a database trigger and all write paths; preserve global protocol uniqueness and report collisions without inventing identifiers or merging records.
- Keep BI positive-volume filtering in a browser-safe visualization helper and its regression test, so zero-demand departments stay hidden without changing public aggregate queries.
- Keep the health-unit donut and its separate legend in HealthUnitChart so chart sizing never depends on the number of legend entries.
- Keep map icon choices in `secretarias.icone` and resolve markers through the shared icon catalog, so all map views honor the same persisted selection.- Regra: políticas do TanStack Query (staleTime por prefixo, retry, limpeza no logout) ficam em src/lib/query-policies.ts — um só lugar para ajustar cache.
- The 1Doc agent (local-docker/agente-1doc) runs only as a queue worker on the VPS reading onedoc_jobs; never run a browser inside the web server, since workerd cannot.
- Normalize legacy worker links in the pure local-docker/agente-1doc/url.mjs helper with regression tests; unwrap encoded email links without visiting third-party redirectors (only 1Doc's own 1docmail.com.br tracking links are followed, via manual redirects) and only allow credential-free HTTP(S) destinations on the real 1Doc domain.
- Scoped 1Doc batches pass explicit IDs through the shared queue endpoint; only explicitly selected location batches may include completed rows, so a scoped action never falls back to a global batch.
- Apply 1Doc writes through a service-only transactional RPC with optimistic conflict checks and trigger-based field audit; authenticated admin reversals restore one latest unchanged field and address coordinates atomically, so audit failures never leave unaudited writes.
- 1Doc history persists department snapshots in job context and full per-protocol outcome snapshots only after successful writes; shared paginated history reads remain admin-only so later edits cannot rewrite audit results.
- Track browser-started 1Doc jobs in a user-scoped authenticated-layout provider with session storage recovery; page buttons only enqueue, so navigation cannot cancel completion notifications or cache refreshes.
- Edit manual 1Doc links through a focused control in the shared protocol detail dialog using the existing protocol URL field; save only the link and refresh detail/list caches so imported rows follow the same flow without completing triage or changing other fields.
- VPS updates: build-vps.yml paths-ignore must match IGNORAR_BUILD in local-docker/atualizar.sh, and a downloaded build is accepted when its commit lies between the last build-affecting commit and HEAD, so multi-commit pushes never cause endless re-downloads.
- The in-app update button only enqueues a row in atualizacao_jobs; the host service ouvidesk-atualizador (local-docker/agente-atualizacao) polls the queue and runs atualizar.sh outside Docker, writing step/log back to the row — the app never executes atualizar.sh itself, since it cannot reach git/Docker from inside the container.
- Scoped e-SIC mailbox searches (buscarEsicPorNumeros in esic-mailbox.server.ts) filter by provider-side subject search (Gmail q / IMAP SEARCH) and only ingest numbers whose chaveNumeroEsic matches the requested set, always reusing ingerirEmail with recheckEsic so dedup by externalId and triagem_pendente stay identical to the full backfill.
- Every database change in drizzle/migrations must also ship as an idempotent numbered file in local-docker/atualizacoes-banco/, because atualizar.sh only applies that folder on the VPS.
