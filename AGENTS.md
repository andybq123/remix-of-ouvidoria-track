# Project rules
- Protocol list pagination uses security-invoker database reads with fixed 50-row pages, server-side global filters and numeric ordering; return only card fields and fetch full records on detail open, so access policies and bounded transfers remain intact.
- Apply selective JavaScript obfuscation only to lazy client license chunks during production builds via tooling/obfuscation.ts; keep source files, SSR, workers, exports and property names unchanged and disable distributed source maps. Keep build tooling outside build/ because global ignore rules exclude that output directory from delivery.
- Keep VPS host, app, worker images and CI on the same patched Node LTS baseline; enforce host minimums through local-docker/node-runtime.sh and refresh images before restart, because changing a Docker tag alone leaves installed host and worker runtimes vulnerable.
- Restrição de áreas de usuários de leitura fica em `user_secretarias` vinculada por e-mail em minúsculas (o usuário pode ainda não estar registrado); a política de leitura de protocolos trata ausência de vínculos como acesso a todas as áreas e exclui ouvidorias sem secretaria de usuários restritos.
- O mapa filtra os botões Saúde/Obras pelas áreas do usuário via `escoposMapaPermitidos` em src/lib/map-departments.ts, consultando `user_secretarias` sempre com filtro do próprio e-mail (admin enxerga vínculos de todos pela RLS, então sem o filtro ele herdaria escopo alheio).
- `secretarias` e `locais` têm policy de SELECT para `authenticated` (além da de `anon`): sem ela, usuários não-admin veem as telas Saúde e Mapa vazias, pois essas telas leem as duas tabelas diretamente.
- Full e-SIC mailbox backfills use resumable bounded requests across all provider pages/folders, separate from incremental sync cursors; reuse ingestion with original received dates and never reprocess linked logs.
- Enforce e-SIC identifier equality in a database trigger and all write paths; preserve global protocol uniqueness and report collisions without inventing identifiers or merging records.
- Keep BI positive-volume filtering in a browser-safe visualization helper and its regression test, so zero-demand departments stay hidden without changing public aggregate queries.
- Keep the health-unit donut and its separate legend in HealthUnitChart so chart sizing never depends on the number of legend entries.
- Keep map icon choices in `secretarias.icone` and resolve markers through the shared icon catalog, so all map views honor the same persisted selection.- Regra: políticas do TanStack Query (staleTime por prefixo, retry, limpeza no logout) ficam em src/lib/query-policies.ts — um só lugar para ajustar cache.
- The 1Doc agent (local-docker/agente-1doc) runs only as a queue worker on the VPS reading onedoc_jobs; never run a browser inside the web server, since workerd cannot.
- Normalize legacy worker links in the pure local-docker/agente-1doc/url.mjs helper with regression tests; unwrap encoded email links without visiting third-party redirectors (only 1Doc's own 1docmail.com.br tracking links are followed, via manual redirects) and only allow credential-free HTTP(S) destinations on the real 1Doc domain.
- Scoped 1Doc batches pass explicit IDs through the shared queue endpoint; only explicitly selected location batches may include completed rows, so a scoped action never falls back to a global batch.
- Apply 1Doc writes through a service-only transactional RPC with optimistic conflict checks and trigger-based field audit; authenticated admin reversals restore one latest unchanged field and address coordinates atomically, so audit failures never leave unaudited writes.
- 1Doc history persists department snapshots in job context and full per-protocol outcome snapshots only after successful writes; shared paginated history reads remain admin-only so later edits cannot rewrite audit results.
- Track browser-started 1Doc jobs in a user-scoped authenticated-layout provider with session storage recovery; page buttons only enqueue, so navigation cannot cancel completion notifications or cache refreshes.
- Edit manual 1Doc links through a focused control in the shared protocol detail dialog using the existing protocol URL field; save only the link and refresh detail/list caches so imported rows follow the same flow without completing triage or changing other fields.
- VPS updates: build-vps.yml paths-ignore must match IGNORAR_BUILD in local-docker/deploy/atualizar.sh, and a downloaded build is accepted when its commit lies between the last build-affecting commit and HEAD, so multi-commit pushes never cause endless re-downloads.
- The in-app update button only enqueues a row in atualizacao_jobs; the host service ouvidesk-atualizador (local-docker/agente-atualizacao) polls the queue and runs `deploy.sh atualizar` outside Docker, writing step/log back to the row — the app never runs it itself, since it cannot reach git/Docker. Installs and manual root updates call the idempotent agente-atualizacao/instalar.sh (skipped when OUVIDESK_AGENTE_ATUALIZACAO is set), so a running job is never killed.
- All VPS operations go through the root deploy.sh menu (instalar/atualizar/dominio/ferramentas) with shared helpers in local-docker/deploy/comum.sh; local-docker/atualizar.sh stays only as a one-line wrapper because old installed services still call that path.
- Deploy license checks use licenca_url() for local LICENCA_URL overrides and the versioned LICENCA_URL_B64 fallback; invalid encoding fails closed, no configured URL disables checks, and curl errors never log endpoints. Keep sources editable and share this resolver with heartbeat; encoding is not a security boundary.
- Scoped e-SIC mailbox searches reuse the bounded full-backfill cursor across every provider page/folder with provider-side subject filtering; only ingest requested normalized numbers and surface per-message failures without aborting the batch, preserving linked logs and original dates.
- Every database change in drizzle/migrations must also ship as an idempotent numbered file in local-docker/atualizacoes-banco/, because deploy applies only that folder on the VPS; tests/instalacao/run.sh applies schema + that folder twice on a clean Postgres and deploy/conferir-instalacao.sql must list any new critical table/function/policy.
- References to users from imported data are cleaned by public.limpar_vinculos_usuarios_inexistentes() (FKs to auth.users with SET NULL plus created_by/updated_by/criado_por columns); call it after any import path so missing users never break ingestion.
- Read-only users get edit rights only via allowed_emails.pode_editar (admin-managed); protocol UPDATE for them is RLS-gated by pode_editar_area() to their areas and non-triage rows, while triage, delete and 1Doc stay admin-only.
- Triage access = admin OR posso_editar() (pode_triar() in DB, usePodeTriar in UI); read-only users never see triage, and deleting protocols stays admin-only.
- Audit business changes through registrar_alteracao (admin-only reads), excluding license state; authenticated service actions use a request-local adminComAutor client with a service-only actor header, and 1Doc derives the initiator from the persisted job inside its transactional RPC, never from record ownership.
- Area access = area_permitida(secretaria, local): user_secretarias grants a department minus locais.area_propria; user_locais grants only that local (UI id "local:<uuid>"); no links = everything.
- License lock: VPS heartbeat (local-docker/deploy/heartbeat-licenca.sh, systemd timer) writes public.licenca_estado; the generic statement trigger bloquear_se_licenca() refuses writes from app roles while blocked (re-run public.aplicar_bloqueio_licenca() after creating tables), ingestion routes/agent check it explicitly, and UI uses useLicencaBloqueada() — keep the decision rule in src/lib/licenca-estado.ts in sync with the shell script.
- Dashboard reads protocols via RPC dashboard_protocolos() (positional arrays) rebuilt in src/lib/dashboard-dados.ts; keep column order in sync so payload stays small under RLS.
